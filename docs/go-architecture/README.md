## 文档权威性

本目录取代 [早期可行性方案](../go-rewrite-plan.md) 中的实现性建议，特别是：

- 使用独立 `data/go/melokeep.db`，旧数据库只读导入，不共用原数据库逐域修改。
- 生产切换前用隔离副本比较；迁移期不部署两套同时写正式曲库的服务。
- v1 正式支持受控 Mutagen helper 负责多容器标签写入；音源内置 7 个开放许可/官方试听源，扩展来源通过 Goja JS 插件沙箱承担。
- 对通知的保障是本地去重、幂等调度及不确定交付处理，不承诺外部系统端到端 exactly-once。
- 包目录和任务依赖以本目录为准；早期人日估算不是代理必须赶上的期限。

冲突处理：跨模块职责以 architecture.md 为准；数据库列/索引/文件日志以 storage-and-recovery.md 为准；旧公开行为与 helper wire 协议以 compatibility-contracts.md 为准。执行文档不能自行改变这些契约。任何交叉冲突必须由集成负责人修订对应文档后再实现，不允许各代理各选一种解释。

## 已决定与仍需验证

已决定：Go 单体、现有 React、SQLite 本地数据库、单实例写入、固定 helper 边界、旧 API 兼容层、明确业务服务、逐模块实现但一次生产写权切换。

待实验确认：SQLite 驱动性能、目标文件系统持久化能力、特殊 TLS/代理模式、标签格式回归、稳定性能预算。各项都有 T01 验证任务和失败替代方案；不能以“待验证”为理由让实施代理任意改架构。

## 完成的定义

全部功能有归属；全部旧接口有明确处理；内置开放音源与插件沙箱均有契约和限制记录；数据导入和回滚经过演练；关键故障测试通过；支持平台的构建、前端回归和同负载性能基准通过。满足这些要求才叫“全功能 Go 后端迁移完成”。保留受控 Mutagen 标签工具必须在发行说明中披露。

本轮只产生设计、清单及执行手册，不改业务代码、不迁移真实数据、不触发生产发布。
